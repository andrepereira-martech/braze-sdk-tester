# Analytics Demo — Braze Report Setup Guide

Instructions for building analytics reports after running the **Analytics Demo** scenario in the API Tester.

---

## Important: What the Seeded Data Can and Cannot Do

The scenario seeds 53 users with **backdated custom events** (up to 90 days in the past). This matters for which reports work out of the box:

| Report | Works with seeded data? | Why |
|---|---|---|
| Analytics → Overview (MAU/DAU) | ✅ Yes | Braze counts backdated session events |
| Analytics → Custom Events | ✅ Yes | Event frequency charts use historical data |
| Analytics → Revenue | ✅ Yes | Backdated purchases appear in revenue charts |
| Segment building | ✅ Yes | Attribute/event filters work regardless of date |
| Email Performance / Heatmap | ⚠️ Requires real send | Opens and clicks only come from Braze's sending pipeline — use the **Canvas Trigger** panel to send directly from the API Tester |
| Canvas Funnel Report | ⚠️ Limited | Only counts events that happen **after** Canvas entry — backdated events are excluded |
| Canvas Retention Report | ⚠️ Limited | Same constraint — only post-entry events count |

For the Funnel and Retention demos, see the options in Steps 3 and 4.

---

## Step 1 — Create a Segment to Isolate These Users

1. Go to **Audience → Segments → Create Segment**.
2. Name it *"Analytics Demo Users"*.
3. Add filter: **Custom Attribute** → `demo_scenario` → *equals* → `analytics-demo`.
4. Save. This segment is used as the entry audience for the Canvas and as a filter in all reports.

**Optional sub-segments:**

| Sub-segment | Filter | Purpose |
|---|---|---|
| High Engagers | `demo_cohort` = `high` | Power users, full funnel |
| Medium Engagers | `demo_cohort` = `medium` | Mid-funnel drop-off |
| Low Engagers | `demo_cohort` = `low` | Retention baseline |
| Admins | `role` = `Admin` | Role-based targeting demo |
| Course Creators | `role` = `Course Creator` | Role-based targeting demo |

## Step 2 — Build & Launch a Canvas

> Required before Email Performance, Heatmap, Funnel Report, and Retention Report are accessible.

You have two options:

- **Option A — Build from scratch** in the Braze Dashboard (see the full walkthrough in [Building a Test Canvas from Scratch](#building-a-test-canvas-from-scratch) below).
- **Option B — Use an existing Canvas** and trigger it from the API Tester (skip to Step 2a).

If building from scratch:

1. Go to **Messaging → Canvas → Create Canvas**. Name it *"Analytics Demo — Onboarding Journey"*.
2. Set **Entry Schedule** to **API-Triggered** (this allows the API Tester to trigger entry).
3. Set **Entry Audience** to the *Analytics Demo Users* segment.
4. Add a **Message step** → select **Email**. Build a simple email with at least one clickable link (use the Articulate template if available).
5. **Launch** the Canvas (it must be active to accept API triggers).

> **Note:** Email opens, clicks, heatmap, and deliverability data are generated by Braze's sending pipeline only — they cannot be seeded via the API. A real send is required.

## Step 2a — Trigger the Canvas from the API Tester

> Use this after building or selecting a Canvas in Step 2. This replaces the manual "Send Test" workflow.

**Post-scenario trigger (recommended):**

1. Run the **Analytics Demo** scenario as usual (Step 1 should already be done).
2. After the run completes, expand the **"Trigger Canvas for these users"** section that appears below the results.
3. Click **Load Canvases** to fetch your Canvas list.
4. Select the Canvas you built in Step 2.
5. Optionally set `canvas_entry_properties` (e.g. `{"source": "api-tester"}`).
6. Click **Trigger Canvas**. The seeded users will enter the Canvas and receive the email.

**Standalone trigger (for re-triggering or different users):**

1. Scroll to the **Canvas Trigger** section in the API Tester.
2. Click **Refresh** to load your Canvas list.
3. Select the target Canvas.
4. Enter the `external_id` values (one per line) — you can copy these from a previous scenario run.
5. Click **Trigger Canvas Send**.

Wait **30–60 minutes** for engagement data to process before viewing reports.

## Step 2b — Run the Refresh Scenario (Enables Funnel & Retention Data)

> Run this **after** launching the Canvas in Step 2, using the **same prefix** as the original seed.

The original scenario seeded backdated events (up to 90 days ago) which the Canvas Funnel and Retention Reports cannot see — they only count events that occur after Canvas entry. This refresh scenario re-fires the key events at current timestamps so both reports populate.

**In the API Tester:**
1. Select **Analytics Demo — Refresh Timestamps for Canvas Reports**.
2. Enter the **same prefix** used when running the original Analytics Demo scenario.
3. Click **Run**. 53 users, ~20 seconds.

**What it fires per user group:**

| Group | Funnel events fired | Retention sessions |
|---|---|---|
| High (18 users) | `started_trial`, `created_course`, `created_lesson`, `subscription_purchased` | Day 0, 1, 2, 3 |
| Medium first half (10 users) | `started_trial`, `created_course`, `created_lesson` | Day 0, 1, 2 |
| Medium second half (8 users) | `started_trial`, `created_course` | Day 0, 1 |
| Low (17 users) | `started_trial` | Day 0 only |

**Expected funnel counts:** 53 → 53 → 36 → 28 → 18

**Expected retention by demo day (Day 3):**
- Day 0: 53/53 = 100%
- Day 1: 36/53 = 68%
- Day 2: 28/53 = 53%
- Day 3: 18/53 = 34%

> Braze stores future-dated events (`+1`, `+2`, `+3` days) and includes them in analytics on the appropriate calendar date — no re-runs needed.

## Step 3 — Funnel Report

> Accessed from within the Canvas analytics page. **Max 5 steps** (Step 1 "Entered Canvas" is fixed). Run the refresh scenario first.

1. Go to **Messaging → Canvas → [your canvas] → Analytics**.
2. Click the **Funnel Report** tab.
3. Add these 4 steps:

   | Step | Event | Expected count |
   |---|---|---|
   | 1 | Entered Canvas | 53 (100%) |
   | 2 | `started_trial` | 53 (100%) |
   | 3 | `created_course` | 36 (68%) |
   | 4 | `created_lesson` | 28 (53%) |
   | 5 | `subscription_purchased` | 18 (34%) |

4. Set date range and conversion window to **90 days**. Click **Run**.

## Step 4 — Retention Report

> Accessed from within the Canvas analytics page. Run the refresh scenario first.

1. Stay on **[your canvas] → Analytics** and click the **Retention Report** tab.
2. Set **Retention Event** to **Custom Event** → `app_session_started`.
3. Set date range to the past **90 days**. Click **Run**.

**Expected curve by demo day:**
- Day 0: 100% (all 53)
- Day 1: 68% (36 users)
- Day 2: 53% (28 users)
- Day 3: 34% (18 users)

## Step 6 — Report Builder

1. Go to **Analytics → Report Builder → Create New Report**.
2. Click **Add Canvas/Campaign** and select your canvas.
3. Add the following metric columns:
   - **Email:** Sends, Unique Opens, Unique Clicks, Unsubscribes
   - **Custom Events:** `created_course`, `created_lesson`, `created_block`, `subscription_purchased`
4. Set date range to past **90 days**. Click **Save & Build Report**.
5. Optionally pin to a dashboard: **Analytics → Dashboard Builder**.

## Building a Test Canvas from Scratch

This walkthrough creates a Canvas specifically designed for testing engagement messaging statistics with the API Tester. The Canvas uses API-triggered entry so you can fire it directly from the app.

### Prerequisites

- A Braze workspace with a REST API key that has `canvas.trigger.send` and `canvas.list` permissions.
- The **Analytics Demo Users** segment from Step 1 (or any segment containing your test users).
- At least one email address on the test users that can receive mail.

### 1. Create the Canvas

1. Go to **Messaging → Canvas → Create Canvas**.
2. Name it *"API Tester — Engagement Test Canvas"*.
3. Optionally add a tag: `api-tester` (makes it easy to find in the Canvas Trigger panel).

### 2. Configure Entry

1. Set **Entry Schedule** to **API-Triggered**.
   - This is critical — it allows the API Tester's `/canvas/trigger/send` call to push users into the Canvas.
2. Under **Entry Audience**, select the *Analytics Demo Users* segment.
   - This acts as a guardrail: only users matching the segment can enter, even if the API sends other IDs.
3. Set **Entry Controls** → **Allow users to re-enter this Canvas**: choose *Yes* if you want to test multiple sends to the same users.

### 3. Build the Message Flow

1. Click **+ Add Step** → **Message**.
2. Name it *"Welcome Email"*.
3. Select **Email** as the channel.
4. Build the email:
   - **Subject:** `Welcome to the Analytics Demo`
   - **Body:** Include at least **two clickable links** (these generate heatmap data):
     ```
     <a href="https://example.com/get-started">Get Started</a>
     <a href="https://example.com/learn-more">Learn More</a>
     ```
   - Use any template you like — the key is having trackable links.
5. (Optional) Add a **Delay step** (e.g. 1 day) followed by a second **Message step** with a different email to test multi-step funnel analytics.

### 4. Launch

1. Review the Canvas summary.
2. Click **Launch Canvas**.
3. The Canvas is now active and waiting for API triggers.

### 5. Trigger from the API Tester

1. In the API Tester, go to the **Canvas Trigger** section.
2. Click **Refresh** — your new Canvas should appear in the list.
3. Select it, enter the `external_id` values of your test users (or use the post-scenario trigger after running the Analytics Demo).
4. Click **Trigger Canvas Send**.

### 6. Verify Delivery

1. In Braze, go to **Messaging → Canvas → [your canvas] → Analytics**.
2. You should see:
   - **Entered:** the number of users you triggered
   - **Sent:** emails dispatched
   - **Delivered / Opened / Clicked:** will populate as recipients interact with the email
3. For per-user verification, go to **Users → User Search** → look up a test `external_id` → **Messaging** tab to see the Canvas entry and email delivery events.

### Tips

- **Re-triggering:** If entry controls allow re-entry, you can trigger the same users multiple times to build up volume for reports.
- **Entry properties:** Pass `canvas_entry_properties` like `{"source": "api-tester", "test_run": "2026-03-16"}` to tag sends for easier filtering in Currents/Snowflake.
- **Multiple channels:** Add push or SMS steps alongside email to test cross-channel reporting (requires the corresponding channel setup in Braze).
- **Conversion events:** Set a conversion event on the Canvas (e.g. `subscription_purchased`) to see conversion rate analytics alongside delivery metrics.
